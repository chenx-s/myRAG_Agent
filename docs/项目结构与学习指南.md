# 项目结构与学习指南

> 这份文档面向**回顾学习**：告诉你项目里每一块是什么、代码在哪个文件哪个函数、
> 该按什么顺序读。配合 `docs/新增代码与功能说明.md`（讲"改了什么、为什么"）一起看。


## 一、RAG 主链路：5 个文件各自负责什么

### 1.1 `app/document_processer.py`（244 行）—— 把文件变成文本块

**职责**：整个链路的第一环，磁盘文件 → `Document` 对象列表。

| 函数 | 行号 | 作用 |
|---|---:|---|
| `load_document(file_path)` | 41 | 按后缀分派 Loader（PDF/TXT/MD/DOCX/HTML/CSV），返回 Document 列表 |
| `load_directory(dir_path)` | 128 | 递归遍历目录，逐个调 `load_document`，单个文件失败只跳过 |
| `clean_text(text)` | 174 | 去行首尾空白 + 删空行 |
| `split_documents(docs)` | 192 | 递归字符分块，产出最终入库的 chunk |

**关键概念**：
- **metadata 是溯源的基础**。每个 Document 带 `source`（路径）、`filename`、`page`（PDF 页码）、
  `start_index`（块在原文的位置）。后面 API 返回的"引用来源"全靠它。
- **chunk_size / chunk_overlap 是最值得调的参数**。太大夹带噪声，太小语义不全。
- **递归切分**：按 `["\n\n", "\n", "。", "；", " ", ""]` 从粗到细尝试，尽量在语义边界断开。

### 1.2 `app/vector_store.py`（724 行）—— 存取 + 检索


#### 第一块：向量化与连接

| 函数 | 行号 | 作用 |

| `get_vector_store()` | 256 | 组装 `Milvus` 对象（**`enable_dynamic_field=True` 在这**） |

#### 第二块：BM25 稀疏检索

| 函数 | 行号 | 作用 |
|---|---:|---|
| `_append_corpus(docs)` | 307 | 把文本追加写入 `bm25_corpus.jsonl` |
| `load_corpus()` | 329 | 读回语料副本 |
| `_tokenize(text)` | 371 | 分词：jieba 优先，否则英文按词 + 中文单字 + 相邻二元组 |
| `get_bm25_retriever()` | 408 | 构建 BM25 倒排索引 |

**这是整个升级里最该理解的一块**：为什么 Milvus 存了文本，还要另存一份 JSONL？
—— 因为 Milvus 不提供"把全库文本拉出来建倒排索引"的高效接口。
这叫**倒排索引持久化**，是最简单可靠的做法。

#### 第三块：RRF 融合

| 函数 | 行号 | 作用 |
|---|---:|---|
| `rrf_fuse(rank_lists, top_k, weights)` | 457 | 多路结果按排名融合 |
| `_doc_key(doc)` | 438 | 去重键 = `source + md5(内容)` |

```
RRF 公式：score = Σ weight_i / (RRF_C + rank_i)     RRF_C = 60
```

**核心洞察**：稠密检索给余弦相似度（0~1），BM25 给无上界的词频分（可能 0.3 可能 27.5）。
**量纲不同不能直接相加**。RRF 只看排名不看分数，巧妙绕开了这个问题。

### 1.3 `app/rag_chain.py`（1008 行）—— 编排：检索与生成怎么串

**职责**：用 LangGraph 把各个步骤组成一张**可回退、可重试**的状态图。

#### 第一块：状态定义

| 定义 | 行号 | 作用 |
|---|---:|---|
| `GraphState(TypedDict)` | 77 | 全图共享状态，**读它的注释能理解整张图** |

> 节点函数的约定：接完整 state，**只返回要更新的字段**，LangGraph 自动合并。
> 所以"改了却没 return"的修改会被丢弃。

#### 第二块：提示词模板

| 提示词 | 行号 | 用途 |
|---|---:|---|
| `DOC_GRADE_PROMPT` | 146 | 判断文档能否回答该问题 |
| `REWRITE_PROMPT` | 161 | 改写查询 |
| `MULTI_QUERY_PROMPT` | 175 | **多查询裂变**（RAG-Fusion） |
| `HYDE_PROMPT` | 194 | **HyDE 假想答案** |
| `GENERATE_PROMPT` | 210 | 生成答案（要求数字原样引用） |
| `GENERATE_STRICT_PROMPT` | 229 | **严格模式重生成**（新增） |
| `GROUNDEDNESS_PROMPT` | 250 | **忠实性检查**（含中英数字换算表，新增） |
| `FALLBACK_ANSWER` | 288 | 拒答话术 |

#### 第三块：组件与工具

| 函数 | 行号 | 作用 |
|---|---:|---|
| `get_llm(**kwargs)` | 57 | GLM 客户端（关掉 thinking 模式） |
| `get_reranker()` | 297 | Cohere Reranker（多版本兼容导入） |
| `normalize_question(q)` | 352 | 问题规范化 |
| `_parse_yes_no(text, default)` | 372 | 解析 LLM 的 yes/no 输出 |
| `_parse_query_list(text, limit)` | 390 | 解析裂变出来的查询列表 |
| `_doc_grader()` / `_groundedness_grader()` | 415 / 420 | 两个评分器 LLM |
| `_format_context(docs)` | 425 | 把检索到的文档拼成上下文 |

#### 第四块：图节点

| 节点 | 行号 | 做什么 |
|---|---:|---|
| `transform_query` | 444 | **①** 查询变换：1 个问题 → N 条查询（none/multi_query/hyde） |
| `retrieve` | 504 | **②** 混合检索（调 `multi_query_search`） |
| `rerank_documents` | 527 | **③** Cohere 精排（失败降级透传） |
| `grade_documents` | 581 | **④** 逐条评分：这段真的能回答吗 |
| `rewrite_query` | 611 | **⑤** 全不相关时改写查询 |
| `generate` | 655 | **⑥** 生成答案（按 `strict_grounding` 选提示词） |
| `check_groundedness` | 699 | **⑦** 忠实性检查 + 触发重生成 |

#### 第五块：条件路由

| 函数 | 行号 | 决策逻辑 |
|---|---:|---|
| `decide_after_grading` | 808 | 有相关文档→generate；否则→rewrite（或超限→generate 兜底） |
| `decide_after_rewrite` | 825 | 改写有效→回 transform_query；无变化→generate |
| `decide_after_groundedness` | 837 | 未通过且还有额度→**回 generate 重生成**；否则→END |

| 定义 | 行号 | 作用 |
|---|---:|---|
| `build_graph()` | 852 | **把节点和边接起来——想看全图就看这个函数** |
| `RAGChain` | 910 | 对外封装，`answer()` 是主入口 |

## 二、一次 `/query` 的完整旅程

把这条链路读懂，整个项目就通了。假设你问：**"Llama 2 的参数量是多少？"**

```
【1】main.py:368  query()
      │  收到 JSON，Pydantic 校验（不合法直接 422）
      ▼
【2】rag_chain.py:910  RAGChain.answer()
      │  填充初始 GraphState，交给状态图
      ▼
【3】rag_chain.py:444  transform_query
      │  QUERY_TRANSFORM=multi_query → LLM 裂变出 3 条查询：
      │     "Llama 2 的参数量是多少？" / "Llama 2 有多少参数？" / "LLaMA 2 parameter count"
      │  → state["queries"] = [4 条（含原问题）]
      ▼
【4】rag_chain.py:504  retrieve
      │  调 vector_store.py:552  multi_query_search(queries)
      │     ├─ 对每条查询：
      │     │    ├─ dense_search  → BGE 向量化 → Milvus 检索 Top-20
      │     │    └─ sparse_search → BM25 检索 Top-20
      │     │    └─ rrf_fuse 融合成一路
      │     └─ 再把 4 条查询的结果再 rrf_fuse 一次
      │  → state["documents"] = 融合后 20 条候选
      ▼
【5】rag_chain.py:527  rerank_documents
      │  Cohere Cross-Encoder 把「问题+每篇文档」拼起来重新打分
      │  20 条 → 只留最相关的 5 条（分数 0.87 / 0.80 / 0.73 / 0.69 …）
      │  （Cohere 挂了就跳过，透传原候选）
      ▼
【6】rag_chain.py:581  grade_documents
      │  LLM 逐条判断"这段能回答这个问题吗"，过滤无关的
      ▼
【7】决定路由（decide_after_grading）
      │  有相关文档 ────────────────► 去第 8 步
      │  全不相关 → rewrite_query 改写问题 → 回到第 3 步（最多 2 轮）
      ▼
【8】rag_chain.py:655  generate
      │  把 5 条文档拼成上下文 + 问题 → GLM 生成答案
      ▼
【9】rag_chain.py:699  check_groundedness
      │  让 GLM 当裁判：答案里每句话都能在文档里找到依据吗？
      │  ├─ 通过 → 结束
      │  └─ 不通过 → strict_grounding=True → 回第 8 步用严格提示词重写一次
      ▼
【10】main.py:222  _to_source()
      │  把 Document 转成 SourceInfo（含 relevance_score / rrf_score）
      ▼
【11】main.py:368  返回 QueryResponse
       answer + sources + queries + groundedness + …
```

**读代码时对着这条链路走一遍，每个函数的输入输出就都清楚了。**
